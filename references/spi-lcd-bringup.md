# 4 线 SPI 小屏（240×320 TFT）bring-up

适用：SPI（4 线：SCK/MOSI/CS/DC + RST/BL）TFT 模块，常见控制器 ST7789 / ST7789P3 / ST7789V / ST7796 / ILI9341。
目标顺序：**先证线束 → 再证模块活着 → 再核引脚定义 → 最后才是驱动序列**。

---

## 1. 自检三件套（不靠逻辑分析仪）

| 目的 | 做法 | 判据 |
|---|---|---|
| 线束通 | 把 SCK/MOSI/CS/DC 临时配成 GPIO 输出 1kHz 方波，万用表直流档量屏座 | 每根 ≈1.6V（真驱动）。读到 3.3V 是模块内部上拉造成的悬空假象 |
| 模块活着 | 同一排线上的第二颗芯片（GT911 触摸、EEPROM）I²C 应答 | 应答 = 供电/地/插接都好，故障范围缩到“控制器 + 显示相关几根线” |
| 位序/模式 | 对照原厂驱动的位操作：SCK 空闲低 + 数据在 SCK 低时建立 = **模式 0**，先发 bit7 = **MSB first** | 与 HAL 的 `CLKPolarity=LOW / CLKPhase=1EDGE / FirstBit=MSB` 对齐 |

引脚顺序**只认模块原厂原理图**，板端网表只代表自己这一侧；常见错位是成对对调（电源两脚、BL/TE、TP_RST/TP_INT）。

---

## 2. 控制器子型号要先确认

- 规格书/丝印写 `ST7789P3` 就按 P3 的表；用通用 ST7789 表可能全黑（寄存器集与上电时序不同）。
- 卖家网盘/商品附件常带**能跑的 Keil 工程**（`TFT_init()` 或 `LCD_Init()`），这是这块屏的确定答案；优先于 Adafruit 等通用库。拿不到就直接向用户要。
- **从压缩包里挖序列的具体做法**：解压后别只搜 `LCD_Init`——厂家函数名各异（`TFT_init`、`LCD_Init`…），按 `grep -E "0x3A|0x2A|TFT_SEND_CMD|WriteComm"` 找初始化块更可靠。国内厂家的 `.c` 多为 **GBK** 编码，直接读是乱码，用 `open(f,'rb').read().decode('gbk','replace')` 转一次再读。商品页只给规格书时，规格书上的控制器型号（如 `ST7789P3`）本身就是关键信息。
- 同名控制器差异可能出现在：`0xD0` 写几次、`0xD6`(CMD2EN)、`0xB7`、`0xBB`、`0xC3`、`0xE0/0xE1` Gamma 表、是否发 `0x01` SWRESET、`0x13`、`0x21` 的位置、`0x11/0x29` 与 `CASET/RASET` 的先后。

---

## 3. ST7789P3 原厂初始化表（240×320 IPS，金逸晨 T280C7 系列实测）

硬复位：`RST=0` 100ms → `RST=1` 100ms。**不发 SWRESET，不发 0x13。**

```
B2 : 0C 0C 00 33 33        PORCTRL
36 : 00                    MADCTL (竖屏; 0x60 镜像 / 0xC0 180°)
3A : 55                    COLMOD 16bpp
B7 : 55                    GCTRL
BB : 1A                    VCOMS
C0 : 2C                    LCMCTRL
C2 : 01                    VDVVRHEN
C3 : 19                    VRHS
C6 : 0F                    FRCTRL2
D0 : A7                    PWCTRL1  —— 第一次
D0 : A4 A1                 PWCTRL1  —— 第二次（少写这次常见全黑）
D6 : A1                    CMD2EN
E0 : F0 03 09 0B 0A 16 2B 33 41 38 14 14 29 2F     Gamma +
E1 : F0 04 06 09 08 04 2B 32 41 36 12 12 2A 30     Gamma -
21                          INVON（IPS 必须开，少了是反色/发白，不是黑）
2A : 00 00 00 EF           CASET 0..239
2B : 00 00 01 3F           RASET 0..319
11 + 120ms                  SLPOUT
29                          DISPON
2C                          开始写显存
```

顺序是关键：`0x21` → `CASET/RASET` → `SLPOUT` → `DISPON` → `0x2C`，与常见“SLPOUT 在前”的写法不同。

**CS 粒度**：原厂是每个命令/每个数据字节各自 `CS=0 … CS=1`；初始化阶段照抄。像素连发阶段**不许想当然合并**——有的模块整帧拉低会花屏、有的直接全黑，只能按第 8 节的阶梯实测（逐字节 → 逐行 → 整屏）。

## 4. SPI/GPIO 配置要点

- **四根线的含义要能一句话说清**（用户会问）：`SCK` 时钟；`MOSI/SDA` 数据（单向）；`CS` 片选（低有效，拉低才选中这块屏）；`DC` 命令/数据选择（低=命令，高=数据）。其余：`RST` 硬复位（低有效）、`BL` 背光。

- **只写不读 → `SPI_DIRECTION_1LINE`**。开 2LINES 会把 MISO 脚配成 AF，而板内那根脚可能已被占用（编码器、风扇 TACH、第二路 UART），会造成“屏和另一个功能互相拆台”。
- H7 系列：SPI1/2/3 的**内核时钟默认取 PLL1Q**，没开 PLL 时 SPI 完全没时钟，`HAL_SPI_Transmit` 每次等 TXP 超时 → 屏全黑但代码不报错。显式设 `RCC->D2CCIP1R.SPI123SEL = CLKP(per_ck)`。
- 先降到 8MHz 以下排除速度因素，点亮后再提。
- 背光 `BL`：确认是高有效还是低有效（板上常经 MOS 管），点亮测试时先常开。

## 5. 点亮测试画面

一次就想要能判的信息量：

```
fill(黑)
rect(0,   0,  W, H/4, 红)      /* 0xF800 */
rect(0, H/4,  W, H/4, 绿)      /* 0x07E0 */
rect(0, H/2,  W, H/4, 蓝)      /* 0x001F */
rect(0, 3H/4, W, H/4, 白)      /* 0xFFFF */
```

判读：全黑=没数据；只有背光=初始化没生效；花屏=时序/位序/CS 粒度；颜色互换=MADCTL 的 RGB/BGR；上下颠倒=MADCTL MY/MX。

再补一个"寻址"判据：整屏单色之后画 **上红下蓝两块**（各占一半高度）。分界线正好在中间 = 窗口寻址（`2A/2B`）与行推进都对；分界线偏 / 多出横带 / 斜纹 = 窗口参数错或每帧字节数错，两者要分开验。

**这类 4 线模块没有 MISO，显存读不回来**：12P 排针只有 SCL/SDA 单向 + DC/CS/RST/BL/TE（TE 在板上常常悬空）。ST7789 的 `0x2E RAMRD`、`0x09 RDDST` 都需要 SDA 反向输出，实际用不了。所以"到底显示了什么"只能靠**已知图案 + 用户目视**判断，不要在方案里写"读回显存校验"，也别向用户承诺能读回。

**计数器不等于画面**：`HAL_SPI_Transmit` 返回 `HAL_OK`、驱动里 `g_spi_ok` 累到几千、`g_spi_err=0`，只能证明字节离开了移位寄存器，**不能证明屏收到了**（CS 时序、DC、帧粒度错时照样零错误）。拿"传输成功计数"当验收判据会白放行一轮。

多参数盲扫时给每组留**编号 + 不同底色**（同时用背光闪 N 下做冗余），让用户报“第几组有反应”，比让他描述画面可靠。

## 6. 结果回传（RTT）

RTT logger 只打印“抓到之后”的数据，开机日志经常在主机连上前就写完并滚掉。做法：把一次性测试结果（RPM、地址、阶段号、颜色组号）存成全局，在主循环心跳帧里周期性重打一行；这样任何时刻接上都能看到，也方便掉电后重读。

---

## 7. 编辑固件源码的注意点

用正则/替换类工具批量改 C 源码时，源码里的 `"\r\n"` 字面量容易被工具解释成真实换行，导致字符串被拆成多行、编译报 `missing terminating "`。批量改含转义字符的源码时，用脚本以 raw 字符串读写（Python `r'''…'''`），或改完立刻 `make` 确认字符串没被破坏。

## 8. 刷屏速度与 CS 帧粒度（H7 实测）

先算理论下界，才知道慢在哪：`时间 = 字节数 × 8 / SPI 时钟`。240×320 每像素 2 字节 = 153,600 B；16MHz 纯传输 77ms，2MHz 是 614ms。

| 帧粒度 | 一屏 153,600 B 实测 | 结论 |
|---|---|---|
| 每字节一帧 | HAL 每次调用：**1754ms**（≈11.4µs/字节）；寄存器直写：**628ms**（≈4.1µs/字节） | 能稳定显示；耗时由**每帧开销**决定，不是时钟 |
| 每行一帧（480 B） | **215ms** | 本类 12P 模块实测**不可用**（黑屏/花屏）；换模块要重验 |
| 整屏一帧 | 花屏 | 该模块不接受，退回上一档 |

**判据**：实测 ≈ 理论传输时间 → 时钟受限，去提时钟；实测远大于理论 → 帧开销受限，去加大每帧字节数或改寄存器直写。只看“慢”就去换时钟，等于白改一轮。

**改帧粒度/CS 语义时，必须把所有写路径一起改。** 驱动里通常有不止一个发送点：整屏填充、矩形块、字模、图标、窗口设置。只改了 `fill_rect` 而 `draw_char` 仍按旧粒度整块发，现象就是**背景、色块、分隔线都正常，唯独文字/图标不出现**——很容易误判成“字库坏”或“窗口错”。改完先 `grep -n "HAL_SPI_Transmit\|wr_frame\|SPI2->TXDR" drv/*.c` 把所有发送点列出来逐个确认，再用图案验收（一块底色 + 白块 + 一行字，三者同时在场才说明三个路径都对）。

**帧长做成编译期宏，一档一档试**，别每次手改函数体：`#define ST7789_FRAME_BYTES 16`，`fill_rect` 按 `chunk = min(FRAME_BYTES, 行长)` 切片、按整像素（2 字节）对齐。顺序 1 → 16 → 64 → 240，每档单独烧录看画面，坏一档退回上一档。

**找到能正常显示的配置后先把配置冻结**：把「帧粒度 + SPI 时钟 + 初始化表来源」写成宏并注明"已验证可显示，不可随意改动"，然后再做提速。提速阶段一定会改坏，靠宏和注释一次回滚，避免"改着改着忘了哪版是对的"、只能靠用户回忆画面倒推。

**H7 直接写 SPI 寄存器**（省掉 HAL 每次约 10µs 的调用开销）必须按这个顺序，少一步就永远等 EOT：

```c
SPI2->CR1 |= (SPI_CR1_HDDIR | SPI_CR1_SSI);   /* 1LINE 发送方向; 2LINES 可省 HDDIR */
SPI2->CR2  = 1u;                              /* TSIZE = 本次帧数; 不写就不启动 */
SPI2->CR1 |= SPI_CR1_SPE;                     /* 使能外设 */
SPI2->CR1 |= SPI_CR1_CSTART;                  /* 启动传输 */
while ((SPI2->SR & SPI_SR_TXP) == 0u) { }
*(volatile uint32_t *)&SPI2->TXDR = byte;
while ((SPI2->SR & SPI_SR_EOT) == 0u) { }     /* 等这帧发完再抬 CS */
```

**卡死判据**：`info` 停在 EOT 等待循环、`read <SPI_SR 地址>` 读到 **0**、`CR1` 只剩 SSI 位 → 就是 `SPE=0`（外设没使能），不是硬件坏。以 HAL 源码 `stm32h7xx_hal_spi.c` 的 `HAL_SPI_Transmit` 为准：方向位 → TSIZE → SPE → CSTART，四步缺一不可。

**一次只改一个变量**：把“改 CS 粒度”和“提 SPI 时钟”放同一次烧录，只能看到“变好/变坏”，判断不出是谁的作用，必然多花一轮。
