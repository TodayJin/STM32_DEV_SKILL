# SPI 彩屏 + 电容触摸 bring-up 经验（ST7789 / GT911 类模块）

来自 2.8" 240x320 ST7789P3 12P 插接模块（带 GT911 触摸）的实战。适用于同类 SPI 小屏。

## 一、显示：先分清「模块脾气」和「驱动 bug」

1. **CS 帧粒度是一个阶梯，不是模块定律**：先用「每字节 CS」把屏点亮（最保守），**等整条链路都正常（初始化完整、行缓冲尺寸对、能持续出图）之后再单独往粗试**——本项目最后用「一行一帧 CS（640 字节连发）」把整屏从 ~3s 降到 **0.68s**；先前判「这块屏必须每字节」的那次，实际是行缓冲溢出把 SPI 句柄写坏了。
   - 判据：`fill_rect` 里计 `g_last_fill_ms`、整页计 `g_ui_draw_ms`，每次改完读这两个数 + 目视无花屏/错行；出现卡在 `HAL_SPI_Transmit` 等标志或条纹，就退回上一档。三档顺序：每字节 → 一行 → 整屏。
2. **提速率先算下界**：`字节数×8/f_SCK` 是硬件下界，实测远大于它就是每帧调用开销（HAL 每次 ~10µs）。所以顺序是：① 把 CS 粒度放粗（上面那条）② 再提 SPI 时钟（4MHz 起，8/16MHz 逐档试）③ 仍不够再上寄存器级单字节（`CR1.SPE` → `CR2.TSIZE=1` → `CR1.CSTART` → 等 `SR.TXP` → 写 `TXDR` → 等 `SR.EOT` → 清 `IFCR.EOTC`；漏 `SPE` 会死等 `TXP`）。
3. **横屏/旋转**：ST7789 的 MADCTL 四个方向 `0x00 / 0x60 / 0xA0 / 0xE0`（带 MV 位的是横屏）。判据不要靠猜：上电依次切换 4 种，左上角画固定标记 + 大号数字，让用户看哪一种是正的。切换时**宽高要一起换**。
4. **行缓冲必须按最大宽度开**：`static uint8_t line[W*2]` 用竖屏 240 开、切横屏 320 用 → 溢出写坏相邻静态变量（本项目把 SPI 句柄写坏，表现为初始化后卡死）。改成 `[320*2]`。
5. **启动观感**：把背光延后到「首帧画完再开」，用户看到的是黑屏几秒然后整页出现，而不是逐行刷出来。但任何在首帧之前的提示/校准画面都必须在它之前单独开背光，否则用户看到的是黑屏（本项目踩过：校准界面全黑）。
6. **★ 真正的提速手段是 SPI DMA，不是再提时钟**。CS 粒度放粗后仍是「每字节 1.4µs」，因为瓶颈是 `HAL_SPI_Transmit` 的逐字节轮询，不是线速率：实测 32MHz 下整屏填充仍要 224ms（≈680KB/s）。改用 `HAL_SPI_Transmit_DMA`（≥16 字节走 DMA、小块仍轮询）后同一块屏：
   - 整屏填充 320x240（153.6KB）**47ms ≈ 26Mbps**，整页 UI 绘制 **193ms**，`g_spi_err` 归零；
   - **两个必备条件，少一个就卡死**：① **DMA 缓冲必须在 DMA 能访问的 RAM**（H7 的 DTCM 0x2000_0000 DMA 读不到，放 AXI SRAM，如链接脚本的 `.eth_dma` 段）；② **必须实现 `SPIx_IRQHandler` → `HAL_SPI_IRQHandler(&hspi)` 并 `HAL_NVIC_EnableIRQ(SPIx_IRQn)`** —— `HAL_SPI_Transmit_DMA` 靠 SPI 中断收尾，没中断就永远等不到 `State == READY`（现象：整页画不出来、`g_ui_draw_ms` 恒 0、halt 后 PC 停在 SPI/HAL 等待循环）；
   - DMA 还要配 `DMA_HandleTypeDef`（`DMA_REQUEST_SPIx_TX`、MEM_TO_PERIPH、字节对齐、`__HAL_LINKDMA(&hspi, hdmatx, hdma)`）并实现对应的 `DMAx_StreamY_IRQHandler`；
   - DMA 调用失败要**回退到轮询**（`if (st != HAL_OK) HAL_SPI_Transmit(...)`），不要让它变成静默丢帧。
7. **画字：一个字一次 DMA**。逐字符用 `fill_rect` 逐行画（每个字几十次 `set_window`）是第二大开销；改成把字模拼成整块（`6*scale × 8*scale` 像素）→ 一次 `set_window` → 一次 DMA。缓冲按最大 scale 开在 AXI SRAM（scale 5 时 30x40x2=2400B）。
8. **裁剪用运行时宽高，不要用竖屏宏**：`if (x + w > ST7789_W)` 这类宏在横屏下会把 x>240 的文字**整段丢掉**（不报错、不花屏，就是“右边的字没了”）。一律用 `s_w/s_h`（随 MADCTL 更新的变量）。
9. **局部重刷**：每张卡片缓存上次画过的 `(电压, 电流, 状态)`，只有变化才重画对应的小矩形；配合 500ms 节拍，空闲时开销≈0。整页重绘只在换页时做。


## 二、GT911 触摸

0. **先按总线扫描确认到底是哪颗触摸芯片，再决定用哪份厂家驱动**：卖家常同时给多套驱动（GT911 / HYN-CST 系列），目录名与实物不一定对应。扫触摸 I2C（0x08~0x77）看应答地址：GT911 在 0x5D（另可选 0x14），CST 系列常在 0x15/0x1A；再用 `0x8140` 读回 ASCII `"911"` 碻认。地址/PID 对不上就换驱动包，别把 CST 的移植说明往 GT911 上硬套（两套寄存器协议完全不同）。
1. **先确认芯片活着**：读 `0x8140` 应返回 ASCII `"911"`；`0x814E` bit7 = 有新数据，bit3:0 = 点数。
2. **配置区为空**：`0x8047`（配置版本）读 0 表示配置没写进去，芯片会扫描但永远报 0 点。修法：把厂家 `.cfg` 写进 `0x8047~0x80FE`（184 字节），`0x80FF` 写校验（`(~sum)+1`），再写 `0x8040=1` 应用/保存，延时 150ms。
3. **厂家配置从哪来**：卖家量产包里的 `*.cfg` 是**文本**（`0x59,0xF0,0x00,...`），直接正则解析成 184 字节即可，不用找源码。注意有多份（不同批次/旋转方向），版本字节（首字节）不同。
4. **复位时序**（决定 I2C 地址）：INT 低 + RST 低 ≥10ms → 释放 RST（此时 INT 低=0x5D，INT 高=0x14）→ 6ms → INT 再保持低 50ms → 放开 INT（浮空输入）→ 等 50ms。
6. **轮询频率**：触摸读取必须放在主循环每圈；挂在 500ms 的 UI 节拍上会漏掉所有短按（表现为「完全没反应」）。
7. **★ 读完一个点必须清 `0x814E`（写 0）**，否则芯片缓冲区一直「就绪」并重复返回**同一个点**——现象是「不管点哪里，原始坐标都一模一样」，极易误判成触摸层损坏。清之前留 3ms 间隔；清完再读状态应回到无数据。
   - **恒定坐标的第一嫌疑永远是这条**，其次才是复位时序/读法：先把「读点 → 清状态 → 再读」跑通，再谈硬件。
   - 验证法：点两个明显不同的位置，看原始坐标是否变化；不变就查清除，别查面板。
8. **点数据一次事务读完**：从 `0x814E` 连续读 10 字节，布局 `[status][id][xL][xH][yL][yH][sizeL][sizeH][rsv][rsv]`，`x = xL|xH<<8`、`y = yL|yH<<8`。分两次（先读状态、再读 0x8150）在部分批次上会读到错位或残留数据。
9. **只有确认「不同位置点按 → 坐标确实变化」之后**，坐标恒定才可能是触摸层/贴合/配置不匹配；在此之前不要下硬件结论。
10. **点击要沿触发（去抖）**：`gt911_read()` 返回「新按下 vs 持续按住」两种状态（内部用 `pressed` 标志，松手即清），UI 只在**按下沿**响应一次。否则按住不放会每 250ms 触发一次，表现为「点一次开关跳两下 / 长按页面乱跳」。
    **`pressed` 必须在所有「松手」路径上清零**：无事件（`0x814E` bit7=0）那条分支、以及读到「0 个点」后清状态那条分支，**两条都要 `pressed = 0`**。只清其中一条的典型现象是「第一次点击有效，之后点什么都没反应」（所有后续触点都被当成持续按住）——因为除第一次外每次都走另一条分支。修好后典型交互（点卡片进详情→点顶栏返回→进系统页→再返回）要一次跑通再交付。

11. **卖家目录里先列全再解压**：同一个模块的资料夹常同时放多个压缩包（显示例程、触摸例程/驱动、量产配置工具、规格书）。只解压其中一个就得出「没有触摸源码」「只有 cfg 没有驱动」的结论会直接带偏后面几轮；先 `ls` 整个目录，把 `.zip/.7z` 全解开再判断。解压时注意：原生 7z/7z.exe 从 bash 接收中文路径会报「系统找不到指定的路径」——先 `cp` 到一个纯 ASCII 路径（如 `/c/tmp/x.7z`）再用 `C:/tmp/x.7z` 形式传给 7z。

## 三、坐标映射：先定「换轴」，再用靶点标定

0. **旋转屏的映射是「换轴 + 取反」，不是只翻符号**：面板原生竖屏 (x 0..239, y 0..319) 映到横屏 320x240 时，屏幕 x 来自 raw y、屏幕 y 来自 raw x（MADCTL 带 MV 位必然如此）。只写「x←x、y←y 再取反」会得到「手指左右动、光标上下动」——本项目绕了很多轮就栽在这。
   **最快的判定是运动测试**：让用户手指沿屏幕左右滑动，问一句「点是不是也左右动」，再问上下。人眼判「移动方向」比判「偏移多少 / 反没反」可靠得多，一问定轴。换轴后先写死一组量程（如 raw x 0..231、raw y 10..307）验证方向，再进标定。
1. 轴定下来后，映射是**固定线性变换**（面板原生 → 屏幕方向），不是每次上电都要用户标定的东西。屏幕上画**四个已知位置的十字靶**（约 (30,30)/(290,30)/(30,210)/(290,210)），让用户依次点中，记录四对「屏幕坐标 ↔ 原始坐标」：左右两角平均出 raw x 量程、上下两角平均出 raw y 量程，再按线性公式换算：
   `x = sx1 + (rx - rx1) * (sx2 - sx1) / (rx2 - rx1)`，y 同理。分母带符号，**方向反/镜像/缩放不对都会自动吃掉**。
2. 第二点必须与第一点相差 >20（原始坐标），否则一定是残留数据（没清状态/没松手），继续等而不是接受。
3. 取两点时要**等松手**（连续 300ms 无触点）再画下一个靶，否则两次读到同一个位置。
4. 别让用户看**静态**红点判断「偏了多少 / 反没反」（人眼几乎判断不了）；但**运动测试是例外**——「左右滑动时点是否也左右动」一问就能答，是定轴最快的手段。**两点标定只在轴已正确时够用**：轴本身错了，两点会把错误固化成一个看着合理、实际在中心偏 30~40px 的映射，越校越歪。
5. **标定结果要落 Flash，否则每次上电都在等校准**：把两点映射（屏幕上/下的两对坐标）带 magic + CRC 存在最后一个 Flash 扇区，上电先读，有效就直接用；只有读不到或用户主动要求时才进靶点界面。否则现象是「每次复位后屏幕要等很久才出现」——那不是刷屏慢，是在等用户点靶（本项目每靶 8s 超时，两次就是 16s）。首次写入需要擦 128KB 扇区（约 1~2s），只在标定成功那一次付。
6. **标定记录要带「配置版本」一起存**：GT911 的分辨率/旋转来自 `0x8047` 那份配置表，一旦重写配置（换批次 cfg、改旋转），旧的坐标量程就失效了。存标定时把当时读到的配置版本（或量程上下限）一并写下，上电比对不一致就作废重标；否则会出现「换了配置后每个点都偏，但旧标定看起来仍然合法」。

## 四、排查顺序（照这个顺序走，不要跳）

1. 屏幕能出图（每字节 CS + 低时钟）→ 2. 修方向（4 种 MADCTL 让用户选，或按屏上数字自检）→ 3. 提速（CS 粒度放粗 → 提时钟 → **上 SPI DMA**，见一.6/一.7）→ 4. 触摸芯片应答（PID）→ 5. 配置写入（版本非 0）→ 6. **读点后清 `0x814E`** → 7. 两个不同位置的原始坐标确实不同 → 8. 才做映射（两点靶点法）。

任何一步不过，先解决这一步，不要往下猜；尤其不要在第 6 步之前说「触摸层坏了」。

## 五、把人机界面和硬件解耦：先做接口层，再排布局

屏一稳定，用户接下来要的是「先把内部所有功能的接口做好，布局再定」。这时候**不要继续让 UI 直接读 INA238/写 EN 引脚**（本项目 UI 前后重写两次，都是因为数据来源绑死在驱动里）。正确结构：

- 一层 `sys_api`（或同名模块）对外只暴露语义接口：`api_ch_get(i, &info)`（名字/类型/状态/使能/实测有输出/V/I/P/设定值/上下限/限流/故障位一次取全）、`api_ch_set_enable` / `api_ch_set_voltage_mv` / `api_ch_set_ilim_ma` / `api_ch_clear_fault`、`api_sys_get`（uptime/风扇/温度/链路/IP/MAC/端口/版本）、按通道的桥接统计；
- 底下接已有的状态机模块（通道保护/故障锁存）与驱动（INA238/MCP4728/EN 引脚），硬件细节不外泄；
- **通道编号只定义一次**，UI、协议、日志共用同一套编号（本项目驱动里是 48V_1/48V_2/24V_1/24V_2/ADJ_1/ADJ_2，UI 卡片曾按 INA 地址排，两套顺序不一致就会“点 A 路动 B 路”）；
- UI 与将来的 TCP/485 协议都只调这一层：布局重排时只改绘制代码，功能不会跟着抖。

排布局前先确认接口是“一次取全”的（一个结构体拿全一路的状态），否则界面每加一个字段就要再改一次驱动层。
