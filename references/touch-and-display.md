# 触摸与 SPI 屏实战要点（GT911 / ST7789）

## 1. GT911「坐标永远同一个点」的两个必踩点
- **读完一个点必须写 `0x814E = 0`**。缓冲区不清，芯片会一直返回上一帧的点：表现是点哪里坐标都不变，很容易误判成“触摸层坏了”。
- **松手要复位“按下”标志**。只在“有点”分支里置 pressed、松手路径没清，之后所有点击都被当成“持续按住”，只剩第一次点击有效（典型现象：进了某个页面就再也点不出来）。接口做成 `返回 2=按下沿 / 1=按住 / 0=松手`，UI 只响应 2。

## 2. 识别触摸控制器：扫总线，不要猜
- GT911：I2C **0x5D**（或 0x14），PID 寄存器 `0x8140` 读回 `“911”`。
- HYN/CST 系列（cst3xx/6xx/8xx）：**0x15/0x1A**，寄存器是 4 字节地址、协议完全不同。
- 上电先扫 0x08~0x77，总线上的实际器件决定用哪套驱动；厂家可能同一块屏换过触摸芯片。

## 3. GT911 点数据格式与读法
- `0x8150` 起：`[id][xL][xH][yL][yH][sizeL][sizeH][rsv]`。
- **一次事务从 `0x814E` 连读 10 字节**（状态 + 点）最稳；分两次事务读会被中途刷新打断。
- 复位时序：INT 低 → RST 低 >10ms → RST 释放（此时 INT 低 = 地址 0x5D）→ INT 保持低 ~50ms → 放开 INT（浮空/上拉输入）。

## 4. 横屏旋转后的触摸映射
- MADCTL 旋转 90° 后触摸 **X/Y 是互换的**：手指左右动 → 屏幕上绿点上下动，就是这个症状，不是“左右反了”。正确形式 `dx = f(raw_y)`、`dy = g(raw_x)`，再各自定正负。
- 定正负的最快办法：屏幕上画四角标记，点一下就在映射后的位置画点，让用户看“点左上，点出现在哪”。
- 不要用两点标定（一点按偏整屏都歪）；四点 + 取左右/上下平均更稳，做完存 Flash。

## 5. SPI 屏（ST7789）速度四环节
- `HAL_SPI_Transmit` 每次调用固定开销 ~10µs；逐字节 CS + 逐字节调用 = 一屏几秒。先改成“整行/整块一次发”，再提时钟。
- 走 DMA 三件套缺一不可：
  1. 使能 `SPIx_IRQn` 并实现 `SPIx_IRQHandler → HAL_SPI_IRQHandler(&hspi)` —— 否则 `HAL_SPI_Transmit_DMA` 永不完成（表现为卡在等待、超时）。
  2. 发送缓冲必须在 **DMA 可访问 RAM**（DTCM 不行，放 AXI / 自定义段）。
  3. DMA 失败要**回退轮询**，否则一次失败整屏花。
- 实测：2MHz 逐字节 → 32MHz + DMA，320x240 整屏 **3.0s → 47ms**（≈26Mbps）。
- 旋转后所有裁剪判断用**当前方向**的宽高变量，别用竖屏宏（`x + w > 240` 会把横屏右侧文字整段丢掉）。

## 6. 上电毛刺：JTAG 复用引脚的内部上拉
- PB3(JTDO)/PB4(NJTRST) 复位后内部上拉；若这些脚驱动 EN，上电瞬间会把通道打开。
- 软件只能把窗口缩到最小：把拉低放到 **复位入口第一条指令之后**（启动文件 `Reset_Handler` 里 `ldr sp` 之后、`.data` 拷贝之前）。
- 要彻底解决仍需硬件：EN 的 100k 下拉改 **10k**（对抗 ~40k 内部上拉），或换到普通 GPIO。
